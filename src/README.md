# Процедурный прототип AR-визуализатора — КТ2

Проверено на Python **3.14.7**. Используется только стандартная библиотека;
устанавливать пакеты и собирать проект не требуется. В исходниках нет своих
классов. Записи семи сущностей хранятся в списках словарей и сохраняются в JSON.

## Быстрый запуск

Откройте терминал в папке `src` и выполните:

```bash
python3 main.py demo
```

В Windows команда может называться `py -3.14` вместо `python3`.
Программа создаст в `output/demo` звуковой пример `demo.wav`, входной
`input.json` и результат `result.json`.

Ожидаемый вывод:

```text
Анализ: 1; сеанс: 1; кадров: 61
Первый кадр: RMS=0.3535; центроид=1000.02 Гц
Последний кадр: яркость=0.7071; оттенок=0.2500; масштаб=1.7071
Результат: output/demo/result.json
```

Звук — синус 1000 Гц с амплитудой 0,5, длительностью 1 с и частотой
дискретизации 8000 Гц. Размер кадра 256, шаг 128. Полных кадров:
`1 + (8000 - 256) // 128 = 61`. Малое отличие центроида от 1000 Гц связано
с округлением сигнала до 16-битного PCM. Времена запуска в JSON будут текущими.
Масштаб вычисляется как `1 + brightness` при выводе и отдельно не хранится.

## Обработка своего файла

Поддерживается несжатый WAV PCM: один канал, 16 бит. Сначала создайте пример
командой `demo`, затем замените файл или добавьте в `input.json` трек со своими
`track_id`, `title`, `source_uri`, `sample_rate` и `sample_count`.
Путь `source_uri` отсчитывается от папки входного JSON. Частота и число
отсчётов должны совпадать с WAV. Например, обработать исходный пример ещё раз:

```bash
python3 main.py analyze --data output/demo/input.json --track 1 --profile 1 --preset 1 --out output/result.json
```

Готовый пример входного JSON также лежит в `example_input.json`. После команды
`demo` его можно обработать так:

```bash
python3 main.py analyze --data example_input.json --out output/from_example.json
```

Если передать предыдущий `result.json` как вход, программа добавит новый анализ
и новый сеанс с другими идентификаторами. Ранее рассчитанные записи сохранятся.
Пути в `--data` и `--out` должны вести к разным файлам. Если указать один файл,
программа выведет ошибку и не изменит входной JSON. Проверка учитывает разную
запись пути и файловые ссылки на тот же файл. Отдельный файл результата можно
перезаписывать.

## Данные и операции

| Коллекция JSON | Сущность ER-модели | Что хранится |
|---|---|---|
| `tracks` | Track | Метаданные и путь к звуку |
| `profiles` | AnalysisProfile | Размер и шаг кадра |
| `runs` | AnalysisRun | Связь трека с профилем, версия и время анализа |
| `frames` | AnalysisFrame | Индекс кадра, RMS и центроид |
| `presets` | VisualPreset | Коэффициенты визуального стиля |
| `sessions` | VisualizationSession | Анализ и пресет конкретного показа |
| `visual_frames` | VisualFrame | Яркость и оттенок каждого кадра сеанса |

Связь треков и профилей M:N разрешена через `runs`. В `data.py` проверяются
первичные и внешние ключи, уникальность индекса кадра внутри анализа и
принадлежность визуального кадра анализу его сеанса.

| Задача BPMN | Функция |
|---|---|
| Рассчитать спектр кадра | `calculate_spectrum(frame)` |
| Извлечь признаки кадра | `extract_features(frame, spectrum, sample_rate)` |
| Сформировать параметры визуализации | `map_visual_frame(features, preset, previous, sample_rate)` |

В `main.py` эти операции последовательно вызываются для каждого полного кадра.
Консольный вариант рассчитывает параметры сцены. Отрисовка AR выполняется
мобильным приложением и в этот прототип не входит.

## Проверки

```bash
python3 checks.py
```

Ожидается `Пройдено проверок: 10`. Проверяются БПФ против прямого ДПФ, сигнал
известной частоты, тишина, неверные размеры, сглаживание, полный проход по WAV,
повторный анализ, ошибки ключей и несоответствие метаданных звуковому файлу.
Дополнительно проверяется защита входного JSON от перезаписи и сохранение
результата в отдельный файл.

## Ограничения

Используется прямоугольное окно: кадр поступает на БПФ без дополнительного
взвешивания. Для произвольной музыки границы кадра вызывают растекание спектра;
центроид здесь служит простой характеристикой для выбора оттенка. Оценки темпа
и распознавания музыкальных событий в этом варианте нет.

Последний неполный кадр отбрасывается. WAV и результаты целиком находятся
в памяти, поэтому прототип предназначен для коротких записей. Профили и пресеты
при повторном использовании сохраняют свои коэффициенты; для изменения
коэффициентов нужно создать новую запись с новым идентификатором.
